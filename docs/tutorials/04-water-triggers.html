Water triggers: react to entities entering water

Turn a water body into a script trigger, identify the water in a callback, and run gameplay logic when a body enters or leaves.

In this tutorial

  • Create the water
  • Enable the trigger
  • Lua callback
  • C++ callback
  • What triggers and when
  • Troubleshooting

1. Create the water

  1. Choose Create → Water Surface. The editor creates an entity named Water at the current camera target.
  2. Select it and open the Water section in Details.
  3. Set Width, Depth, and the entity's Y position. The water surface is centered on the entity.
  4. Choose a Body Type and tune the look. Waves, refraction, foam, and terrain erosion do not affect trigger detection; the procedural footprint does.

2. Enable the trigger

In the Water section, enable Trigger. This is the checkbox that turns the water into a script trigger volume. It is enabled by default for new water surfaces.

No separate ColliderComponent is required. The trigger follows the water's procedural footprint, including the rounded lake/ocean edge and the river channel, instead of a simple box.

Play mode only. Water trigger events are dispatched while the scene is playing, the same as physics trigger callbacks. Entering and leaving water in the editor camera does not run gameplay scripts.

Objects must have a dynamic Jolt body to be detected. A visual mesh without a collider/rigid body is invisible to the trigger. A character with a dynamic capsule or box body works.

3. Lua callback

Water uses the existing trigger callback API. The trigger id is the water entity; the other id is the body that entered: 

function OnTriggerBeginOverlap(trigger, other)
    local water = Galeshi.world.entity(trigger)
    if not water or not water:has_component("water") then
        return
    end

    print("entered " .. water:name(), "body", other)
end

function OnTriggerEndOverlap(trigger, other)
    local water = Galeshi.world.entity(trigger)
    if not water or not water:has_component("water") then
        return
    end

    print("left " .. water:name(), "body", other)
end

If you need the entity behind other, wrap it the same way: 

local body = Galeshi.world.entity(other)
if body and body:valid() then
    print(body:name())
end

Keep track of active entries when you need a count or a per-entity effect: 

local inside = {}

function OnTriggerBeginOverlap(trigger, other)
    local water = Galeshi.world.entity(trigger)
    if not water or not water:has_component("water") then return end
    inside[other] = (inside[other] or 0) + 1
end

function OnTriggerEndOverlap(trigger, other)
    local water = Galeshi.world.entity(trigger)
    if not water or not water:has_component("water") then return end
    inside[other] = math.max(0, (inside[other] or 0) - 1)
end

Trigger ids are raw numbers. Use Galeshi.world.entity(id) before calling entity methods such as name() or has_component().

4. C++ callback

Hot-reload C++ scripts receive the same events. The callback signature is unchanged: 

#include "GaleshiEngine/Scripting/CppScriptApi.hpp"

static const GaleshiScriptApi* g_api = nullptr;

extern "C" void GaleshiScriptRegister(const GaleshiScriptApi* api) {
    g_api = api;
}

extern "C" void OnTriggerBeginOverlap(uint32_t trigger, uint32_t other) {
    if (!g_api || !g_api->has_component(
            g_api->user, trigger, "water")) {
        return;
    }

    g_api->log(g_api->user, "entered water");
    (void)other;
}

extern "C" void OnTriggerEndOverlap(uint32_t trigger, uint32_t other) {
    if (!g_api || !g_api->has_component(
            g_api->user, trigger, "water")) {
        return;
    }

    g_api->log(g_api->user, "left water");
    (void)other;
}

See C++ gameplay scripts for the module lifecycle and compile/reload workflow.

5. What triggers and when

SituationResult
Body enters the water footprint and becomes partially submerged OnTriggerBeginOverlap fires once with the water entity.
Body leaves the water OnTriggerEndOverlap fires once.
Body moves directly from one water body to another The old water receives an end event, then the new water receives a begin event.
Trigger checkbox is disabled while a body is inside The end event is sent for the current entry. No new events fire until the checkbox is enabled again.
Water entity is disabled or removed Active entries are closed with end events.

The water still applies buoyancy, drag, splash particles, and camera/bubble behavior independently of the trigger checkbox. The checkbox only controls script events.

6. Troubleshooting

ProblemCheck
No callbacks at all Is the scene in Play mode? Is the water Enabled and Trigger checked? Does the script define the global callback?
Player does not trigger the water The detected entity needs a dynamic Jolt body. Add a collider and rigid body to the object that moves through the water.
Water and a manual trigger fire twice Remove the extra trigger collider from the water entity. The water volume itself dispatches the events when its checkbox is enabled.
Trigger fires at an unexpected place Check the water entity's position, width, depth, body type, and the procedural edge. River channels and lake edges are not rectangular.
Logic runs in the editor without Play Use the trigger callbacks rather than a per-frame water check; the callbacks are Play-only.
