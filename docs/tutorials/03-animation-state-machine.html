Tutorial 3

Animation state machines for characters

Create an idle/walk state machine, blend between clips, drive it from Lua, and save a separate setup for every character.

In this tutorial

  • Concepts
  • Import a character
  • Add states and clips
  • Add transitions
  • Drive it from Lua
  • Save per-character setups
  • Troubleshooting

1. Concepts

An animated character has a SkeletalComponent and an AnimationStateMachineComponent on its skeleton root. The state machine contains:

  • States — one animation clip each.
  • Transitions — rules that switch states.
  • Parameters — values such as Speed used by transition conditions.

A state can use a clip embedded in the character model, or a separate animation asset retargeted by bone name. The editor gives every character its own state machine and, when saved, its own .asme file.

2. Import and select a character

  1. Drag a rigged .gltf or .glb character from the Content Browser into the viewport. This creates a model root with a skeleton and its child meshes.
  2. Select the character root in the Outliner. Selecting a mesh child also works: the editor resolves it to the skeleton owner instead of assigning the state machine to the mesh.
  3. Open the state machine editor from Animation → State Machine Editor. Selecting a character opens it automatically.

One character, one state machine. Do not set up animation on a shared parent such as a Player wrapper that contains several characters. The editor resolves a sole character below the wrapper automatically; a wrapper with several characters is intentionally not treated as one character.

3. Add states and clips

The ASME window shows the selected character and its source model. Use the States section:

  1. Click + Add All Clips to create one state per embedded clip. For a manual setup, use + Add State.
  2. Rename the state, for example Idle and Walking.
  3. For an embedded clip, choose it in the Clip combo. For a separate animation file, drag an FBX, glTF, or GLB onto the Animation Asset field, or use Browse.
  4. Click Set on a state to preview it. The Loop and Speed controls affect that state.

A model with no embedded clips can still use a separate animation asset, as long as the target character has a skin and armature. The ASME warnings in the window explain when the character mesh cannot be deformed.

4. Add transitions

The default character setup includes a Speed parameter. Build a simple idle-to-walk graph:

  1. Open Transitions and click + Add Transition.
  2. Set From to Idle and To to Walking.
  3. Set Condition to Greater, Parameter to Speed, and Threshold to 0.5.
  4. Add the reverse transition: Walking → Idle with Less than 0.5.
  5. Set Blend to a small value such as 0.2 seconds to avoid a hard pose snap.
ConditionUse
Bool True / Bool FalseToggle a boolean parameter.
Greater / LessCompare a numeric parameter to the threshold.
TriggerConsume a one-shot parameter set to 1.
AlwaysUnconditional transition; combine with a From state.

5. Drive the machine from Lua

A character is a normal entity handle. Change parameters every frame, or switch states directly: 

local character = nil

function RunOnce()
    character = Galeshi.world.find("Qorlan")
end

function RunAlways(dt)
    if not character or not character:valid() then return end

    local move = Galeshi.input.axis("Vertical")
    local speed = math.abs(move)

    Galeshi.animation.set_parameter(character, "Speed", speed)
end
Galeshi.animation.set_state(character, "Walking")
Galeshi.animation.trigger(character, "Jump")
Galeshi.animation.set_parameter(character, "Speed", 1.0)

The script API finds the state machine on the character or its nearest parent, so use the character root handle when possible. State names are the names shown in the ASME window.

6. Save a separate setup for each character

The ASME window displays the setup path under ASME setup. Click Save ASME Setup to write the current states, transitions, and parameters to: 

assets/scripts/<CharacterName>.asme

Selecting a character loads its own setup from that file when it exists. Reload ASME Setup re-reads the file after external edits. Two characters with the same display name receive stable separate file names; a suffix is added to the later entity so their machines do not share a file.

Workflow: configure the graph, press Set to preview it, then Save ASME Setup. Stopping Play restores the authored scene, but it does not update the .asme file for you.

The in-memory state machine is also stored in the scene. The .asme file is the reusable per-character setup; keeping both in sync is intentional.

7. Troubleshooting

SymptomCheck
“No embedded animation clips” Re-export the FBX with All Actions (or an active action), or assign a separate animation asset to the state.
Character does not deform The model must contain a skin and armature. A static mesh with only animation curves cannot be skinned by separate clips.
Animation is tiny or huge Adjust Animation Scale in the ASME window. A centimeter-authored animation on a meter character often needs 0.01.
Two characters play the same pose Make sure each character has its own skeleton root and its own ASME target. Do not target a shared Player/model wrapper that contains both characters.
Changes disappear after selecting another character Save the setup before switching characters, or use Reload ASME Setup deliberately.
