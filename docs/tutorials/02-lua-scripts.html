Lua scripting: lifecycle, entities, and triggers

Write a gameplay script, move an entity, read input, and react to collider or water trigger events.

In this tutorial

  • Where scripts run
  • Lifecycle callbacks
  • Per-entity scripts
  • Entity handles and movement
  • Input and physics
  • Trigger callbacks
  • Reloading and debugging

1. Where scripts run

Lua scripts live in the project's assets/scripts/ directory. The editor loads assets/scripts/init.lua at startup. You can create another file from the Content Browser's right-click menu (New Lua Script), open it in the Code Editor, and run it with the editor's Reload button.

When a Lua file is run, its global functions such as RunOnce, RunAlways, and the trigger callbacks become active in the Lua state. If you use several files, load the ones you need from init.lua or run the file from the Code Editor.

Keep it small first. A script that prints a message in RunOnce is a good way to verify that the file is actually loaded and running.

2. Lifecycle callbacks

A Lua gameplay script uses two optional global callbacks:

CallbackWhen it runs
RunOnce() Once after the file is loaded or reloaded. Use it to find and cache entities.
RunAlways(dt) Every frame. dt is the elapsed time in seconds.

The older update(dt) function is still accepted as a fallback when RunAlways is absent, but new scripts should use RunAlways. 

function RunOnce()
    print("script loaded")
end

function RunAlways(dt)
    -- dt is in seconds
end

3. Per-entity scripts

A Lua script can also be attached to a specific entity. Select the entity, open Details → Script, and drop a .lua file on the script field. The script runs in its own environment and may define: 

function OnStart(entity)
    -- once after load or reload
end

function OnUpdate(entity, dt)
    -- every frame; entity is a raw id
end

Both callbacks are optional. Wrap the id with Galeshi.world.entity(id) when you need entity methods. This is also how a script can create a water body: 

function OnStart(entity)
    local water = Galeshi.world.create("Water")
    Galeshi.world.add_component(water, "water")
end

add_component currently supports the "water" component. The new entity uses the normal Water defaults and can be selected and edited immediately.

Use the entity script field for logic tied to one object. Use init.lua for global callbacks and project-wide gameplay.

4. Entity handles and movement

Galeshi.world.find(name) returns an entity handle or nil. Store the handle in RunOnce and validate it with valid() before using it: 

local cube = nil

function RunOnce()
    cube = Galeshi.world.find("Cube")
end

function RunAlways(dt)
    if not cube or not cube:valid() then return end

    local position = cube:position()
    local height = 1.5 + math.sin(Galeshi.engine.time()) * 0.5
    cube:set_position(position.x, height, position.z)
end

position() returns a table with x, y, and z fields. The same convention applies to rotation, scale, and vector arguments throughout the Lua API.

Common entity methods include:

MethodPurpose
valid()Is the entity still alive?
name() / set_name(name)Display name.
position() / set_position(x, y, z)Local position.
rotation() / set_rotation(x, y, z, w)Quaternion rotation. Three numbers are treated as Euler degrees.
scale() / set_scale(x, y, z)Local scale.
children()Array of child handles.
has_component(name)Check for an engine component, for example "water" or "collider".

5. Input and physics

Input axes are read with Galeshi.input.axis("Horizontal"). For a visual entity without a rigid body, move the transform directly: 

local player = nil

function RunOnce()
    player = Galeshi.world.find("Player")
end

function RunAlways(dt)
    if not player or not player:valid() then return end

    local move = Galeshi.input.axis("Horizontal")
    player:translate(move * 5.0 * dt, 0.0, 0.0)
end

If the entity has a dynamic Jolt body, use the physics API so collisions and gravity keep working: 

local box = nil

function RunOnce()
    box = Galeshi.world.find("PhysicsBox")
end

function RunAlways(dt)
    if not box or not box:valid() then return end

    local velocity = Galeshi.physics.get_velocity(box)
    local move = Galeshi.input.axis("Horizontal")
    Galeshi.physics.set_velocity(box, move * 6.0, velocity.y, 0.0)
end

A script can also spawn a physics object with Galeshi.physics.create_box(name, x, y, z, size). The final optional argument marks the body as static.

6. Trigger callbacks

Triggers use two optional global functions. They receive raw entity ids, not entity handles: 

function OnTriggerBeginOverlap(trigger, other)
    print("entered", trigger, other)
end

function OnTriggerEndOverlap(trigger, other)
    print("left", trigger, other)
end

The first id is the trigger collider. The end callback fires when the last contact between that pair is removed. Wrap an id with Galeshi.world.entity(id) when you need entity methods: 

function OnTriggerBeginOverlap(trigger, other)
    local triggerEntity = Galeshi.world.entity(trigger)
    if triggerEntity and triggerEntity:has_component("water") then
        print("something entered the water")
    end
end

For collider triggers, add a ColliderComponent with Is Trigger enabled and make sure the moving object has a dynamic rigid body. Water bodies have their own Trigger checkbox; the next tutorial covers that workflow end to end.

7. Reloading and debugging

  • F5 reloads assets/scripts/init.lua and C++ modules.
  • The Code Editor's Reload button runs the currently open Lua file.
  • print() and script errors are written to the Output Log.
  • Reloading a script re-runs RunOnce and replaces global callbacks from that file. Cached entity handles from a previous load can become invalid; check them or find them again.

The complete API surface is in the Lua API reference.
