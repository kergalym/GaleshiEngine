Tutorial 1

Editor basics: build and run a scene

Open the editor, learn the viewport controls, create a small scene, and run it in Play mode.

In this tutorial

  • Open a project
  • Move around the viewport
  • Create a minimal scene
  • Save and run
  • Where scripts live
  • Useful shortcuts

1. Open a project

Start the editor from the build directory. It must run from build/debug/bin (or the equivalent release directory) because shaders and engine assets are resolved relative to the working directory. 

cd build/debug/bin
./GaleshiEditor

If no project is open, the Project Manager appears. Create a project or open an existing one. After the project opens, you can load a scene with File → Load Scene… (Ctrl+O).

Tip: the editor log is the first place to look when something does not load. Keep the Output Log panel visible while following the tutorials.

The Outliner on the left lists entities. Selecting an entity opens its components in the Details panel. Most tutorials start by selecting the object in the Outliner rather than clicking it in the viewport.

3. Create a minimal scene

This scene is enough to test movement, lighting, and Play mode. Build it from the top Create menu.

  1. Ground. Choose Create → Cube. In Details, set its scale to something like 20, 0.2, 20 and move it below the origin. Rename it to Ground in the Outliner if you plan to use scripts that look it up by name.
  2. Light. Choose Create → Directional Light. If the scene is dark, increase its intensity in Details or rotate it so it points down at the ground.
  3. Camera. Choose Create → Camera. Move it up and back so it can see the ground. Keep Primary enabled in the Camera component.
  4. Player. Choose Create → Player. This creates the authored gameplay root with PlayerTagComponent; it is not a visible character mesh. A separate character model can be parented to it or spawned by a script.
  5. Optional physics prop. Choose Create → Collision Shapes → Box, raise the collision shape above the ground, then right-click it in the Outliner and choose Attach Mesh → Cube. In the Collision Shape section, set Body Type to Dynamic if you want it to fall.

A quick smoke test: press Play and check that the camera view is usable. If the viewport looks black, select the primary camera and verify its position and clip planes before adding more objects.

4. Save and run

Use File → Save Scene (Ctrl+S) before running. The Play button sits in the thin bar above the viewport. The same button becomes Stop while the scene is running; Esc also stops Play mode.

In Play mode, scripts run, physics bodies are created, and water and trigger callbacks fire. Stopping Play restores the authored scene state. Changes made only at runtime are not saved.

Save before testing. The renderer and physics integrations are still alpha software. A scene that behaves correctly in the editor can still expose a driver issue in Play mode.

5. Where scripts live

Project scripts live under assets/scripts/. The editor loads assets/scripts/init.lua at startup and on F5. The Content Browser can create new Lua files from its right-click menu (New Lua Script or Create Script Templates).

Double-click a script in the Content Browser to open it in the Code Editor. Use the editor's Reload button to run a Lua file and Compile C++ for a hot-reload C++ script.

Continue with Lua scripting for the script lifecycle and entity API.
